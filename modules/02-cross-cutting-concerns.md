# RAG 测评框架 v2：横切规则

- 设计标识：rag-evaluation-v2
- 审阅状态：Confirmed
- 内容修订：r001
- 依据：[总体架构 r001](00-system-architecture.md)、
  [工程目录 r001](01-directory-layout.md)及 v2。
- 确认范围：配置、校验、错误、权限、提交、幂等、
  执行控制、缓存、审计、兼容、恢复和公共验证要求。

## 1. 配置解析与实验冻结

### 1.1 配置优先级

非秘密配置优先级从高到低为：
1. 显式命令行参数。
2. 白名单中的 RAG_EVAL_ 环境变量。
3. 显式指定的配置文件。
4. 随安装包发布的默认值。

不隐式搜索父目录中的配置文件。
未知配置键、非法枚举、无效预算和重复冲突定义在执行前报错。
YAML 使用安全解析，不执行标签对应的代码或对象构造。

相对路径按声明来源解析：
- 配置文件中的路径：相对于该配置文件。
- 命令行和环境变量中的路径：相对于启动时工作目录。
- 包内资源：通过安装包资源接口读取。

工作区默认位于启动工作目录下的 .rag-eval/。
显式 workspace 配置可以覆盖。
路径解析结果在作业开始时固定，运行期间不随当前目录改变。

### 1.2 配置快照

外部调用前冻结有效配置及其来源，包括：
- 数据、语料、系统及 Adapter 版本。
- 指标、rubric、裁判、主张提取和 mapper 版本。
- split、分组、采样、随机种子和比较规则。
- 并发、缓存、超时、重试与预算策略。
- 访问策略、工具范围、时间条件和计价版本。

浮动别名和 latest 引用在计划阶段解析为明确版本。
无法取得不可变模型版本时记录别名、调用时间和复现限制，
不能宣称重算会得到相同结果。

凭据只保存引用身份，不将解析后的秘密值写入快照。
运行策略变化形成新的配置或作业记录，
不能继续使用旧 manifest 声称条件未变。

plan 可以读取和校验已有引用，不调用外部模型或被测系统。

## 2. 数据校验与表示约定

边界校验依次检查：
1. schema、版本、字段类型和范围。
2. ID 唯一性与引用存在性。
3. snapshot、revision、权限及有效时间的一致性。
4. 对象语义与声明 profile 的要求。
5. Adapter 能力、真实产物和指标依赖。

未知字段默认拒绝。
需要保留外部扩展时使用契约显式声明的扩展区域，
不能通过忽略未知字段掩盖接入错误。

ID 不做隐式数字转换；布尔值不作为数值接受。
业务金额和派生运算使用类型化 Decimal、单位及容差规则。
缺失、未披露、未知和零分别表示。

运行时间戳使用带时区的表示，导出统一为 UTC。
业务 as_of、期间及源文时区保留各自含义。
耗时使用单调时钟；并行 Span 不直接相加作为 E2E。

原始产物摘要针对原始字节计算。
配置摘要针对带版本的规范序列化结果计算。
规范序列化采用 UTF-8、固定字段顺序规则，
拒绝 NaN 和 Infinity；Decimal 等类型的表示由所属契约固定。

源文 quote 保留原始内容。
检索归一化另存版本，不以规范序列化为由改写证据。

业务对象、导入记录和发布 profile 的校验由契约所有者负责。
CLI 和 runner 可以协调校验，不能增加另一套相互矛盾的规则。

## 3. 错误与命令结果

### 3.1 错误分类

错误保留以下维度：
- owner：错误所属模块。
- phase：计划、构建、系统调用、映射、评价、干预、报告或存储。
- reason_code：稳定的 <module-id>.<reason>。
- category：输入、引用、权限、能力、外部调用、超时、
  预算、取消、冲突、存储或内部故障。
- 安全的简短说明、关联对象及 attempt 引用。
- 是否具备重试条件及其依据。

重试提示不等于自动重试许可，
仍需满足冻结策略、剩余预算及调用结果确定性要求。

各模块在自己的 contracts 中定义具体错误。
本节统一分类和转换规则，不建立集中业务异常仓库。

原始 SDK 异常先经过脱敏和分类，
不能直接作为公开日志或报告正文。

### 3.2 错误如何影响评价

| 情况 | 处理 |
|---|---|
| 配置、schema 或版本引用不合法 | 执行前失败，给出明确原因 |
| 导入协议不合法 | 保留导入失败记录，不补造 Run 或 Trace |
| 被测系统实际失败或超时 | 保存真实 Run 状态，按任务成功口径处理 |
| 正常返回但答案违反格式或业务要求 | 由相应指标判断，不与传输失败混淆 |
| 实际产物缺少指标依赖 | 对应指标不可计算 |
| 映射或参考存在歧义 | 保留不确定结论和复核依据 |
| Evaluator 超时、解析或程序失败 | Judgment 为 error，value 为 null |
| 必选测量不足 | 报告覆盖缺口，门禁不能自动通过 |

接入错误和测量故障不能自动转成系统质量失败。
已知系统失败也不能以“没有答案”为由从分母删除。

### 3.3 CLI 结果

CLI 拥有命令结果的输出协议。
机器可读结果包含协议版本、命令、命令完成状态、
结果引用、可选 gate 和结构化错误。

机器可读模式下 stdout 输出结果，
运行进度和安全诊断写入 stderr。

退出码约定：
- 0：命令完成；请求门禁时要求 gate=pass。
- 2：参数、输入或执行前校验失败。
- 3：执行或基础设施故障，无法形成要求的目标产物。
- 4：已形成有效门禁结果，gate=fail。
- 5：已形成有效门禁结果，gate=inconclusive。
- 130：用户中断。

未请求门禁时，命令完成不代表被测系统质量通过。
已完成任务中存在失败 Run 或非 ok Judgment，
应保存在产物中，由报告和门禁解释。

## 4. 身份、权限与敏感数据

P0 是本地 CLI，运行主体由操作系统身份及外部服务凭据确定。
服务登录、会话和网络多租户认证为 N/A：首版没有服务端入口。

本地工作区不宣称具备服务级多租户强隔离。
如需服务化，必须另行确认认证、授权和隔离设计。

执行主体与用例中模拟的用户身份分开：
测评进程可以在授权范围读取 gold，
普通被测调用仍只获得用户可见输入和指定 access_scope。

各模块遵守以下规则：
- Store、缓存和导出读取均检查访问域与策略。
- 内容 hash 相同不能绕过访问授权。
- 原文、参考、生产请求、实际上下文和报告分别控制访问与保留。
- 外部模型只接收符合出域策略的内容。
- 凭据不进入 manifest、正文日志、缓存键明文和报告。
- 受管写入与删除目标必须解析并限制在所属目录范围内。
- 源文与模型返回内容作为数据处理，不作为裁判控制指令。
- 程序化答案验证只执行白名单类型化运算。

实际上下文与脱敏展示分别保存引用及变换版本。
脱敏改变了评价所需事实时，相应评价必须说明限制。

审定导入校验对象 revision、审定人身份来源和权限范围。
P0 文件导入记录本地操作身份；
没有外部签名或身份系统时，不宣称提供不可伪造的多人签核。

## 5. 持久化、提交与并发写入

### 5.1 提交边界

正式读者只读取已提交记录。
本地文件后端采用以下逻辑：

```text
取得目标对象的写入协调权
→ 在同一文件系统的暂存位置写入
→ 完成必要的刷新、格式、引用和摘要校验
→ 提交不可变对象
→ 最后发布 manifest 或提交标记
→ 释放协调权
```

发布 manifest 之前，完整依赖必须已经可读取并通过校验。
跨文件更新不宣称具有文件系统事务性。

单文件原子提交和崩溃持久性依赖目标文件系统，
需通过集成测试验证。
对象存储等后端必须提供等价的条件提交语义后才能替换。

同一 ID 和 revision：
- 内容相同：允许作为同一提交的幂等返回。
- 内容不同：报告冲突，不能覆盖。

### 5.2 并发边界

P0 每个作业使用一个提交协调者，
worker 可以有限并发计算或调用。

worker 不并发追加同一个 JSONL 文件。
协调者提交记录，审计导出从已提交集合生成。

多个进程操作同一发布对象时，需要可靠的排他或条件写入。
不能仅凭 PID 文件存在与否判断锁有效性，
也不能在无法确认时删除其他进程的锁。

具体锁、记录文件、索引和提交标记由持久化所有者设计。
SQLite 事务只覆盖其数据库，不能代替数据库与文件的整体提交协议。

缓存与查询索引可以重建。
正式版本的可见性和内容不能仅由可丢失缓存决定。

## 6. 任务身份、幂等与恢复

区分两层身份：
- 逻辑任务：相同冻结输入下需要完成的一项工作。
- 执行 attempt：该任务的一次真实执行尝试。

逻辑身份包含访问域、作业、case 或构建输入、
stage、配置与依赖版本，以及必要的 repetition。
attempt 身份进一步包含尝试序号。

任务去重不删除 attempt、原始响应和计量记录。
真实重复采样使用不同 repetition，
不能靠复用缓存伪造多次独立生成。

外部调用前记录调用意图及关联身份，
得到结果后尽早保存原始产物，再开展后续评价。

崩溃恢复时分别处理：
- 已提交且依赖有效：复用。
- 尚未开始：按剩余计划执行。
- 明确失败：按冻结策略决定是否重试。
- 可能已发送但结果未知：先检查远端请求或幂等能力；
  无法确认时保留未决原因，不能静默视为未执行。

没有远端幂等保障时，不承诺外部调用 exactly-once。

恢复不覆盖已提交结果。
业务请求重跑必须产生可识别的新 attempt 或 Run 关系。
重新评分只续做评价任务，不隐式增加业务预测。

各模块保留自己的状态机，
不能用统一的 succeeded 字段替代质量、发布或评价状态。

## 7. 超时、重试、取消与预算

### 7.1 超时和重试

分别配置作业 deadline、单次调用 timeout、
重试上限及重试等待策略。
子任务不能超过上层剩余 deadline。

未声明的调用重试默认关闭。
被测系统的重试策略必须在实验前固定，
不能观察到答案错误后增加尝试次数。

仅对明确具备重试条件的故障重试，例如临时限流。
输入错误、权限拒绝、版本不兼容和确定业务失败不自动重试。

结果未知的请求按第 6 节处理。
退避加入抖动，并受 deadline、取消信号及预算约束。

裁判重试、响应格式修复和重新生成业务答案分别记录。
前两者不能被转换为一次新的普通系统调用。

### 7.2 并发和取消

默认并发为 1，按 provider 或本地设备显式调整。
速率、并发和预算限制同时生效。

收到取消或预算停止信号后：
- 停止派发新任务。
- 请求在途调用协作取消。
- 保存已完成产物和在途请求身份。
- 在有限清理时间后结束，并公开未完成范围。

本地取消不等于远端已经停止执行或停止计费。
Adapter 不支持取消时必须记录能力限制。

### 7.3 预算与计量

系统调用、数据合成、评价和干预使用独立预算池。
按任务设置输入、输出、图像、工具轮次、
尝试次数及可用成本等限制。

调用前预留可估计资源，完成后按实际用量结算。
计价缺失或远端计量未知时保留 unknown，
不能按零成本处理。

无法强制执行的预算只标记为观测约束，
不能宣称具有硬上限保证。

所有真实请求的已知成本都被保留，包括失败尝试。
远端幂等重试返回同一计费请求时，
按请求身份去重计费，保留本地 attempt。

缓存复用保留原始 usage 谱系，
本次新增调用成本与历史来源成本分别展示。

预算耗尽后公开剩余任务与配额缺口，
不通过删样本或降低审定要求制造完成状态。

## 8. 缓存、版本与兼容

缓存键包含与结果有关的全部依赖：
访问域、内容摘要、snapshot、用例 revision、
实际上下文、配置、模型、模板、schema、
规则、提取器、normalizer 和 mapper 等版本。

各缓存所有者声明精确依赖。
不能只按 query 或模型名称复用评分。

依赖变化只使相关结果失效。
例如裁判规则更新无需重新解析源文，
事实修改则需追踪其证据、蓝图、用例和验证依赖。

需要真实重复采样或测量冷启动的实验，
显式采用相应缓存策略。

分别维护：
- 安装包版本。
- 各提供方 schema 版本。
- 数据与源文 revision。
- 指标、裁判、mapper 及 profile 版本。
- 作业与评分记录身份。

读者声明实际支持的版本。
不能仅凭版本号相近就假设兼容。

不支持的版本在执行前报错。
转换由所有者提供并记录转换版本，
语义变化形成新数据或评价版本，旧结果保持可追查。

## 9. 日志、审计、部署与回退

默认日志包含关联 ID、阶段、状态、reason_code、
时间和安全计量，不记录完整 query、gold、上下文或凭据。

详细输入输出进入授权产物存储，
日志和报告通过受控引用关联。
第三方 SDK 的调试日志同样受此规则约束。

审计至少覆盖：
- 配置与版本冻结。
- 任务开始、attempt、提交、失败与恢复。
- 审定、发布、撤销和版本转换。
- 访问限制、脱敏与删除导致的可用性变化。

首版以可安装 Python 包部署。
依赖版本锁定，发布前验证安装包导入和选定候选流程。
容器、常驻服务、Kubernetes 和滚动升级为 N/A：
首版没有对应运行单元。

升级先检查读取和存储兼容性。
必要的迁移由数据所有者执行，保留可恢复输入与迁移记录。
程序回退只使用其支持的数据版本；
不能通过静默降级字段让旧程序继续处理新语义。

冻结数据的更正、访问撤销和必要删除均保留允许保存的审计信息。
旧版本因此不可复现时，报告明确说明。

## 10. 公共验证要求与后续边界

测试遵循目录设计，并使用可注入时钟、受控外部响应
和隔离临时工作区验证关键行为。

公共验证至少覆盖：
- 不同配置来源的优先级、相对路径和冻结结果。
- 普通系统输入不含 reference、gold 或审定结果。
- 同 hash 跨访问域不能绕过授权。
- 发布各中断点均不会暴露半成品或覆盖既有版本。
- 并发提交同 revision 的相同与不同内容得到不同处理。
- 远端结果未知时不会静默重复调用。
- 裁判失败后的恢复不重跑业务系统。
- 取消、预算耗尽和缺失计量进入产物与报告。
- 缓存依赖变化会使相应结果失效。
- CLI 退出码区分执行失败、门禁失败和结论不足。
- 不支持的版本被拒绝，转换记录可追查。

以上是计划验证，尚未创建或执行应用测试。

后续模块详设仍需确认：
具体错误码、字段、状态转换、后端提交方案、
缓存依赖、迁移方式、取消能力及验收输入。

本文件确认公共规则，不使任何模块详设或实现候选自动就绪。
下一步选择近期候选，再按提供方契约的依赖顺序细化。
